## Driver Interface (Task D2 — define first; V and you both depend on it)
`mira_tv/driver.py` defines an abstract class `Driver` with exactly these methods:
- `reset_to_screen(screen_cfg) -> FocusEvent`: relaunch app (live) or jump to entry (fixture), replay `entry_steps`, return the first focus event (or raise `DriverError`).
- `press(key: str) -> FocusEvent | None`: press one key, wait `MIRA_SETTLE_MS`, return the newest focus event with `seq` greater than before the press; `None` if focus did not change.
- `screenshot() -> bytes`: PNG of the current screen.
- `close() -> None`.
`FocusEvent` is a dataclass: `seq:int, screen:str, element_id:str, bounds:(x,y,w,h), ts:int`.
- `AdbDriver` (`adb_driver.py`): subprocess `adb` with 20 s timeouts; key presses via `adb shell input keyevent <code>`; screenshots via `adb exec-out screencap -p`; a background thread reads `adb logcat -v raw` lines into a queue and parses them with `telemetry.py`; relaunch = `am force-stop <package>` then `am start -n <package>/<launch_activity>`, wait `MIRA_RESET_WAIT_MS`. On relaunch, reset the last-seen `seq` to 0 (the app restarts its counter).
- `FixtureDriver` (`fixture_driver.py`): simulates a device from a fixture folder.

## Fixture Format (Task D2)
```
fixtures/<name>/fixture.json
fixtures/<name>/shots/<element_id>.png     # full screenshot while that element is focused
```
```json
{
  "package": "string",
  "entry": {"home": "home.drawer.1", "details": "details.btn.play"},
  "elements": {
    "home.drawer.1": {
      "screen": "home",
      "bounds": {"x": 0, "y": 0, "w": 100, "h": 50},
      "edges": {"UP": null, "DOWN": "home.drawer.2", "LEFT": null, "RIGHT": "home.card.1", "CENTER": null, "BACK": null},
      "screenshot": "shots/home.drawer.1.png"
    }
  }
}
```
An edge of `null` means the key does not change focus. An edge to an element of another screen is allowed (that is how exits are modeled). `FixtureDriver.press(key)` follows the edge and returns the new `FocusEvent`.
Provide `fixtures/synthetic_clean/` and `fixtures/synthetic_bugs/` generated by a script `mira_tv/make_synthetic.py` using Pillow: ~8 elements on one `home` screen and ~4 on `details`; focused element gets a colored border in its screenshot (clean) or no border for one element (bugs); `synthetic_bugs` also has one element with no inbound edges (UNREACHABLE) and a pocket of elements with no path to an exit target (TRAP). The element IDs used in `synthetic_*` are only for tests; do not hardcode them in engine code.

### D3 — Graph and explorer (Oct 16–17)
`graph.py`: `Graph` with nodes (id, screen, bounds), edges (from, key, to|None); methods `reachable_from(id)`, `shortest_path(a, b)` (BFS), `reverse_reachable(targets)`.
`explore.py`: `explore_screen(driver, screen_cfg) -> ScreenResult` with this exact algorithm:
```
e0 = driver.reset_to_screen(cfg); queue=[(e0.element_id, [])]; seen={e0.element_id}; probes=0
shots[e0.element_id] = driver.screenshot()
while queue and probes < cfg.max_probes:
  (el, path) = queue.pop(0)
  for key in [UP, DOWN, LEFT, RIGHT, BACK]:
    if probes >= cfg.max_probes: break
    ensure the driver is currently focused on `el` (if not: reset_to_screen + replay `path`)
    ev = driver.press(key); probes += 1
    new = ev.element_id if ev else el          # no event = focus stayed
    graph.add_edge(el, key, None if ev is None else new)
    if ev and new not in shots: shots[new] = driver.screenshot()
    if ev and ev.screen == cfg.screen and new not in seen and len(path)+1 <= cfg.max_depth:
        seen.add(new); queue.append((new, path+[key]))
    if ev and key in (UP,DOWN,LEFT,RIGHT):
        back = driver.press(inverse(key)); probes += 1
        graph.add_edge(new, inverse(key), None if back is None else back.element_id)
        # if focus is not on `el` now, the "ensure" step above resets and replays
    elif ev and key == BACK: force a reset on the next iteration (screen may have changed)
```
Record bounds from events into the graph. Return `ScreenResult(graph, shots, probes)`.
**Acceptance:** exploring `synthetic_clean` visits every element; probe count ≤ `max_probes`; a second run on the same fixture gives an identical graph (determinism).

### D4 — Detectors (Oct 17–18)
`detectors.py`, pure functions, each returns a list of `Defect(type, screen, element_id, path, detail)`:
- `detect_unreachable(result, expected_ids)`: every id in `expected_elements[screen]` not in `graph.nodes` after exploring → `UNREACHABLE`. `path` = `[]`; `detail` = "never focused in N probes".
- `detect_trap(result, exit_targets)`: compute `reverse_reachable` from `exit_targets` plus any node on a different screen. Every visited node not in that set is trapped. Report one `TRAP` defect for the first trapped node in BFS order, `path` = shortest path from the screen entry to it; `detail` lists how many nodes are in the trapped region.
- `detect_no_indicator` lives in `vision.py` (D5).
Defect IDs follow `<TYPE>:<element_id>` from BUILD.md. Sort defects by (screen, type, element_id) for deterministic output.
**Acceptance:** golden tests: `synthetic_clean` → zero defects; `synthetic_bugs` → exactly the planted `UNREACHABLE` and `TRAP` defects.

### D5 — Focus-indicator check (Oct 18)
`vision.py`: `indicator_diff(shot_focused, shot_other, bounds) -> float` = mean absolute pixel difference over the element's bounds region between a screenshot where the element is focused and one where it is not (use the screenshot of the element's graph neighbour). Pillow only. If `bounds` are all zeros → return `None` and skip with a note. `detect_no_indicator(result)`: element is defective if `indicator_diff < MIRA_INDICATOR_DIFF_MIN`. `path` = shortest path from entry.
Also `annotate(png_bytes, bounds, color) -> bytes` drawing a 6 px rectangle (red for before, green for after) and downscaling to max width 1280.
**Acceptance:** synthetic fixtures give a high diff for bordered elements and ~0 for the planted one.
**Tuning (with V, Oct 18):** run on `fixtures/real_*`; adjust `MIRA_INDICATOR_DIFF_MIN` so real defects are found and no false positives appear; record the final value in `.env.example`.

### D6 — AI explanation layer (Oct 18)

- System prompt (fixed string in code, version constant `PROMPT_VERSION = "1"`): "You are a TV app QA assistant. A deterministic test already proved the defect described. In at most 60 words, explain what a remote-control user would experience and the most likely cause. Do not change the verdict."

- Call: `boto3.client("bedrock-runtime", region_name=AWS_REGION, config=Config(read_timeout=30, retries={"max_attempts": 2}))`, `converse(modelId=BEDROCK_MODEL_ID, system=[...], messages=[...], inferenceConfig={"maxTokens": 200, "temperature": 0})`.
- Modes: `stub` → deterministic template text, source `stub`; `cache` → read `ai_cache/<key>.json`, source `cache`, on miss fall back to `stub`; `live` → call Bedrock, write cache, source `bedrock`. Cache key = sha256(`PROMPT_VERSION` + model id + defect id + sha256(image bytes)). Count calls; stop at `MIRA_MAX_AI_CALLS`; any exception → `stub` text and a logged warning (never crash a run).
- CLI `python -m mira_tv ai-ping` sends one text-only test call and prints OK/FAIL (never the key).
